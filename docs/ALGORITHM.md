# 分帳與最少轉帳的計算

## 金額與匯率

資料以十進位字串保存，計算全部使用 BigInt。不得將金額轉為 Number 後再計算。TWD／USD 等採 2 位最小單位、JPY／KRW 0 位、KWD 3 位。新台幣零小數尾碼只在顯示時省略，沒有以元截斷計算。

單筆來源／換算金額上限 10^15 最小單位；匯率最多 8 位小數，是使用者指定的固定值，不是銀行牌告或即時報價。先計算 `原始金額 − 折扣 + 小費`，須大於零。退款沿用正數輸入，在總帳反向沖銷。

共同付款金額與指定分攤金額須精確加總為調整後原幣總額；百分比最多 2 位且加總恰為 100%；權重最多 6 位、合計須為正。

原幣總額以有理數匯率換算一次，以 half-up 捨入至本位幣最小單位。付款人依原幣墊款比例、分攤人依均分／百分比／權重／指定原幣金額比例，以最大餘數法各自分配同一筆本位幣總額，避免個別四捨五入造成金額消失。原幣有一分錢的項目不會因換算任意變成整筆額外費用。

對同一組平均分攤成員，以累積的最小單位餘數輪替起點。退款先回退輪替起點，再分配退款，讓相同費用及其完整退款能抵銷。編輯／刪除費用會重新計算這些尾差，所以後續某人的應分攤可能改變一個最小單位。每筆仍保留可檢查的整數分攤，不宣稱匯率或銀行實際兌換無價差。

每人淨額：`淨墊款 − 應分攤 + 已確認轉出 − 已確認收到`。正數應收，負數應付。待確認及已刪除還款不計入；已確認紀錄只計入一次。修改費用後從總帳重新推導餘額，不在上次結算結果上重複扣款。

## 精確最少筆數

前提：只看淨額；所有成員可互轉；沒有禁止配對、單筆轉帳上限、銀行手續費或最小金額限制。不同條件是不同最佳化問題，不能沿用此保證。

去除零餘額，剩 n 位，總和為零。一張可結清的轉帳圖，每個連通分量的淨額和必須為零；若最多能分成 k 個零和分量，任何方案至少需要 n − k 條邊。反過來，每個零和分量可用至多 size − 1 次收付款配對結清，因此下界可達，真正最少就是 n − k。

以 bitmask 儲存子集合。`sum[mask]` 是其 BigInt 淨額和。

```
dp[0] = 0
dp[mask] = max(dp[mask without i] for i in mask) + (sum[mask] == 0 ? 1 : 0)
```

dp 的意義：排列 mask 內成員，最多有幾個零和前綴。每個零和前綴之間形成一個零和分量；任何零和分割也可串接成這樣的排列，所以完整集合 dp 正好等於 k。parent 還原排列，再於各分量內配對債權債務。另有獨立 `verifySolution` 從原餘額逐筆套用，確保只轉正數、端點有效、沒有多算，最後全為零。

時間 O(n 2^n)，空間 O(2^n)。最多 18 位非零餘額使用精確 DP，於 Web Worker 執行，不阻塞主介面。19～100 位使用最大債務／債權貪婪配對，明確標示「近似、未證明最少」，仍驗證全部結清。人數是非零餘額人數，不是帳本人頭總數。

獨立測試使用另一種「枚舉異號配對、遞迴抵銷」的窮舉法，比較隨機小案例的最少筆數，不讓測試只複製 DP 邏輯。

## 需求的 11 人案例

總額 43,813 TWD，11 人各 3,983。正淨額為 5,087、3,222、22,587，負淨額為 −3,449、−3,549、六筆 −3,983。精確 DP 找到 k=1，且測試另枚舉全部 2^11−2 個非空真子集，沒有任何零和子集。因此所有可行轉帳圖必須連通，至少需要 11−1=10 筆；求解器給出的 10 筆方案達到下界。這是求解後的結果，不是預先假設使用者給的方案最優。最佳解可能不只一組，介面不強求逐筆與範例同序。

## 對象簡單模式

選定一位統籌，其他成員只與此人往來。先收負淨額成員的款，再支付其他正淨額成員。每位非統籌至多一位對象，但統籌承擔較多筆數及經手風險；沒有最少總筆數保證。工具不會實際收錢，也不驗證銀行已入帳。
